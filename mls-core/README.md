# mls-core

The single cryptographic core for group messaging, shared by the Android and
Windows clients. Design: [`../docs/mls-v2-architecture.md`](../docs/mls-v2-architecture.md).

**Phase 0 contains no MLS.** It exists to prove the build, the C ABI, and the
buffer/error/panic contracts *before* OpenMLS is introduced, so Phase 1 adds
cryptography behind a boundary that is already tested. The previous design's
worst bugs (`Path required but not present`, unserializable group state) were
only ever reproducible on real devices, one 15-minute rebuild at a time. This
directory is the fix for that: everything provable in a unit test happens here.

## Prerequisite

Rust is not currently installed on this machine. Install once:

```bash
winget install Rustlang.Rustup
```

Then, for the Qt/MinGW ABI used by the Windows client, and the Android targets:

```bash
rustup default stable-x86_64-pc-windows-gnu
```

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
```

`x86_64-pc-windows-gnu` matters: the Windows app is built with MinGW
(`D:\Qt\Tools\mingw1310_64`), so an MSVC-ABI `.dll` would not link cleanly.

## Build and test

```bash
cd /d/messenger_app/mls-core && cargo test
```

```bash
cd /d/messenger_app/mls-core && cargo build --release
```

Artifacts:

- `target/release/mls_core.dll` — loaded by the Qt client
- `target/release/libmls_core.a` — if static linking is preferred later
- `include/mls_core.h` — generated by cbindgen at build time, never hand-edited

## What the Phase 0 tests assert

| Test | Contract |
|---|---|
| `round_trip` | string in, owned bytes out, correct value |
| `null_name_is_an_error_not_a_crash` | NULL args return a code |
| `null_out_is_an_error_not_a_crash` | NULL out-pointer is survivable |
| `panic_is_contained` | a Rust panic becomes `MLS_ERR_PANIC`, never UB in the host |
| `double_free_is_not_possible_via_empty_buf` | freeing an empty buffer is a no-op |
| `abi_version_is_stable` | `ABI_VERSION` only changes deliberately |

## Phase 0 exit criteria

1. `cargo test` green on Windows.
2. `cargo build --release` produces a `.dll`, and `--target aarch64-linux-android` an `.so`.
3. `mls_core.h` generated.
4. Qt calls `mls_ping` and prints the reply.
5. Kotlin calls `mls_ping` through JNI and logs the reply.
6. Both hosts check `mls_abi_version()` at startup and refuse to run on mismatch.

Items 4–6 are the remaining Phase 0 work; 1–3 need only the toolchain.

## Rules carried in from the previous attempt

- No secret crosses the FFI. Not private keys, not epoch secrets.
- No MLS logic in Kotlin or C++. If either parses an MLS structure, the design
  has been violated.
- Rust allocates, the host frees via `mls_buf_free`.
- `panic = "unwind"` stays: `catch_unwind` is what keeps a Rust bug from being
  undefined behaviour on a user's phone.
- Install a log callback first. A silent diagnostic channel cost a full session.
